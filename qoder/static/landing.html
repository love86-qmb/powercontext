NoteSeek · 课程与文献速查台

把散落的课程笔记、论文摘录、会议记录丢进 seekdb，用一句话找回那一段——并且告诉你它出自哪一篇、哪一小节、第几段。

要解决的问题

学生的资料永远是散的：课程笔记在 Markdown 里、论文摘录在 PDF 里、比赛文档在几十个网页里。 想找「上学期隔离级别那页是怎么说的」，只能靠记忆里的关键词一个个文件翻；翻到了也说不清它出自哪儿，复习时不敢引用。

NoteSeek 把「找得到」和「信得过」一起解决：检索结果永远带出处，可以把命中的原文片段直接贴进复习笔记或论文引用里。

核心功能

语义 + 关键词混合检索

向量路找「意思相近」，全文路找「型号、缩写、专有名词」，两路用 RRF 融合排名——单一方式必然漏。

出处可回查

每条结果带「文档 › 小节 › 片段 #n」，来自入库时存下的元数据，不是事后猜的。

切块带小节标题

把小节标题拼进被向量化的文本：答案常常在标题里（「四种隔离级别」），正文词汇却对不上。

零外部模型依赖

内置本地哈希嵌入，不需要 API Key、不需要下载模型，评审克隆下来就能跑。

它是怎么跑起来的

Markdown 笔记→ 按段落切块（带小节标题）→ 写入 seekdb（向量 + 全文 + 元数据）
一句话提问→ seekdb 混合检索（RRF 融合）→ 带出处的片段

技术栈与分工

Qoder

项目主要开发工作：需求拆解、后端与前端代码生成、切块与检索逻辑、调试；项目网站通过 Qoder Sites 发布。

seekdb

核心检索：片段向量 + 全文索引 + 元数据，混合检索与元数据过滤都在库内完成，写入后刷新索引立即可查。

FastAPI

轻量后端，两个接口 /api/ingest、/api/search，前端是单文件 HTML。

自己跑一遍

docker run -d --name seekdb -p 2881:2881 oceanbase/seekdb:latest
cd qoder && pip install -r requirements.txt
SEEKDB_HOST=127.0.0.1 python app.py --ingest samples/notes
SEEKDB_HOST=127.0.0.1 python app.py --port 8090

# 打开 http://127.0.0.1:8090

完整的运行说明与验证样例见仓库中的 qoder/README.md。
