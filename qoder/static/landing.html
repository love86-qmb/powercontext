课程与文献速查台

把 Markdown 笔记切块存进 seekdb，用一句话检索，返回带出处的原文片段——出处形如「文档 › 小节 › 片段 #n」，看一眼就知道该翻回哪一段。

解决的问题

笔记越记越多，能搜到关键词，却找不到那句话到底在哪一段。

语义搜得到，位置找不到

纯关键词只能撞词面。这里每条命中都带出处三元组，文档、小节、段号一次给全。

出处不能靠猜

切块时就把小节归属写进 metadata，片段只从属于它自己的小节，不会出现整库片段都挂同一个标题。

检索栈太贵

seekdb 一个引擎同时给向量、全文和混合检索，不用再单挂 Elasticsearch / Milvus，也不用自己写融合排序。

核心功能

六步做出来：设计 → 切块 → 导入 → 检索 → 前端 → 命令行与文档。

结构感知的切块

段落边界优先，块 ≤520 字符、重叠 60 字符，代码围栏内不断块，front matter 与一级标题行不进正文。

混合检索 + RRF

全文路取最长词做 $contains，向量路走 knn，RRF 窗口与常数各取 60；后端不支持时自动回退向量并标注 mode。

标签下推

tag 转成 where 同时压进全文路和向量路两个分支，不是拿结果再过滤。

整目录导入

python app.py --ingest samples/notes，逐篇报片段数与 doc_id，一篇坏文件不中断整批。

失败要响

seekdb 连不上就 500。空结果与查不到是两件事，接口绝不把故障糊成 count=0。

零依赖前端

单文件 HTML，无框架无 CDN；所有文本走 textContent，笔记里的尖括号与和号只会是文本。

Qoder 与 seekdb 的分工

项目全程只靠六条 prompt + 六条验收推进，每步留一张截图作为开发记录。

Qoder：写代码、也抓 bug

按步产出 chunk_markdown / ingest_document / search / HTTP 层 / 前端 / 命令行入口，并当场用脚本验收。改掉的问题都留在记录里：重叠对齐把 60 字符吃成空串、seq 该按小节还是按文档编号、混合检索静默返回空列表、连接失败必须冒泡成 500。

seekdb：一个引擎管检索

HNSW + cosine 向量索引、IK 分词的全文索引、DBMS_HYBRID_SEARCH 的 RRF 融合、metadata 标量过滤与 refresh_index()，全部由 pyseekdb 官方 SDK 直接调用；应用层只负责切块和拼出处。

本地跑起来

Python 3.10+，seekdb 服务端 ≥1.3（嵌入式模式受 pylibseekdb 平台标记限制，Windows 需连服务端）。

# 起 seekdb
docker run -d --name seekdb -p 2881:2881 -p 2886:2886 oceanbase/seekdb:latest

# 装依赖、指连接
pip install -r requirements.txt
export SEEKDB_HOST=127.0.0.1:2881
export SEEKDB_COLLECTION=noteseek_samples

# 导入示例笔记（4 篇 / 16 片段）
python app.py --ingest samples/notes --tag samples

# 起服务，打开 http://127.0.0.1:8090/
python -m uvicorn app:app --host 127.0.0.1 --port 8090

# 自查：5 个问题打印「命中的文档 / 出处小节 / 耗时」表
python selfcheck.py

已知限制

  • 中文语义路偏弱：默认 embedding 是英文 all-MiniLM-L6-v2（384 维，建集合时定死），中文查询主要靠全文路和 RRF 兜住；换中文模型要连维度一起改并整库重建。
  • 只有命令行导入：没有 POST /api/ingest，网页端不能投稿。
  • 重导入会留孤儿：upsert 让同一片段幂等，但小节改名或删段后旧片段不会被清掉。
  • RRF 分数不是置信度：distance 是排名倒数和，只能比名次；语料只有 16 片段时，Top5 的后几名会自然落到别的笔记。
  • 片段摘要截 160 字符：看整段要拿 doc_id + seq 回查，前端还没做这个跳转。
  • 无鉴权、无分页，共享实例上请用 SEEKDB_COLLECTION 隔离集合名。
