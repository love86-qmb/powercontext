# 数据库事务与隔离级别（课程笔记）

## 事务的 ACID

- **原子性 Atomicity**：事务里的操作要么全做，要么全不做。实现靠 undo log，回滚时按日志反向撤销。
- **一致性 Consistency**：事务把数据库从一个合法状态带到另一个合法状态，由约束（主键、外键、CHECK）和业务逻辑共同保证。
- **隔离性 Isolation**：并发事务之间互不干扰，靠锁和多版本并发控制（MVCC）实现。
- **持久性 Durability**：提交后的数据不丢，靠 redo log 先写日志再刷脏页（WAL，Write-Ahead Logging）。

## 三种并发异常

- **脏读 dirty read**：读到了别的事务未提交的数据，对方一回滚，读到的就是不存在的数据。
- **不可重复读 non-repeatable read**：同一事务内两次读同一行，结果不一样，因为别人改了并提交了。
- **幻读 phantom read**：同一事务内两次按条件查，行数变了，因为别人插入或删除了符合条件的行。

## 四种隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不可能 | 可能 | 可能 |
| REPEATABLE READ | 不可能 | 不可能 | InnoDB 下用间隙锁基本避免 |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 |

MySQL 的 InnoDB 默认是 REPEATABLE READ，靠 MVCC 的一致性读（快照读）避免不可重复读，靠 next-key lock（记录锁 + 间隙锁）避免幻读。

## MVCC 的关键字段

每行记录有两个隐藏列：`DB_TRX_ID`（最后修改它的事务 ID）和 `DB_ROLL_PTR`（指向 undo log 的版本链）。快照读时用 Read View 判断某个版本是否可见：比当前活跃事务最小 ID 还小的版本可见，比最大 ID 大的不可见。

## 锁的类型

- 共享锁 S（读锁）和排他锁 X（写锁）
- 意向锁 IS / IX：表级标记，表示表里有行被加锁，避免逐行扫描判断
- 记录锁、间隙锁、next-key lock：InnoDB 在 REPEATABLE READ 下解决幻读的组合

## 常见考点

- 长事务会撑大 undo log，导致 purge 滞后，进而出现「历史版本读」变慢，生产上要限制事务时长。
- `SELECT ... FOR UPDATE` 是当前读，会加锁；普通 `SELECT` 是快照读，不加锁。
- 死锁检测靠等待图（wait-for graph），InnoDB 会主动回滚代价小的事务并报 1213。
