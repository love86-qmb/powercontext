# 事务与隔离级别

## 三种并发异常

- **脏读 dirty read**：读到别的事务未提交的数据，对方一回滚，读到的就不存在了。
- **不可重复读 non-repeatable read**：同一事务内两次读同一行结果不同，因为别人改了并提交。
- **幻读 phantom read**：同一事务内两次按条件查，行数变了，因为别人插入或删除了符合条件的行。

## 四种隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不可能 | 可能 | 可能 |
| REPEATABLE READ | 不可能 | 不可能 | InnoDB 下基本避免 |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 |

## REPEATABLE READ 是怎么避免幻读的

InnoDB 默认就是 REPEATABLE READ，靠两套机制配合：

1. **MVCC 一致性读（快照读）**：普通 SELECT 读的是事务开始时的快照，别人插入的行在快照里看不见，所以不会「第二次查多出行」。行上两个隐藏列 `DB_TRX_ID` 与 `DB_ROLL_PTR` 组成版本链，Read View 决定哪个版本可见。
2. **next-key lock（当前读）**：`SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` 这类当前读会加锁。next-key lock = 记录锁 + 间隙锁，锁住记录本身以及记录之间的间隙，别人就无法在间隙里插入新行。

所以严格说：快照读靠 MVCC 避免幻读，当前读靠 next-key lock 避免幻读。

## 锁的类型

- 共享锁 S、排他锁 X
- 意向锁 IS / IX：表级标记，避免逐行扫描判断表里有没有行锁
- 记录锁、间隙锁（gap lock）、next-key lock：REPEATABLE READ 下解决幻读的组合

## 常见考点

- 长事务撑大 undo log，purge 滞后，历史版本读会变慢。
- 普通 SELECT 是快照读不加锁；`SELECT ... FOR UPDATE` 是当前读会加锁。
- 死锁检测靠等待图，InnoDB 会回滚代价小的事务并报 1213。
