# 知识库工程笔记

## 增量导入后为什么要刷新索引

向量索引是异步构建的。写入完成后立刻检索，新数据可能还不在索引里，表现为「导入成功了但搜不到」。
所以写入之后要显式刷新索引（seekdb 里是 `refresh_index()`，pyseekdb 与 seekdb-js 都有这个方法），
刷新完成后新片段才可检索。这是「导入后能搜到」的唯一保证，不能靠等。

## 增量写入与幂等

片段 id 用「文档 + 序号」生成，重新导入同一篇文档时用 upsert 覆盖同一批 id，避免出现重复片段。
但要注意：小节改名或删掉一段后，旧片段不会被自动清理，需要按 `doc_id` 先删后写，否则库里会留孤儿片段。

## 集合与会话状态

多个知识库共用一个集合时，用 `kb_id` 这类元数据字段隔离，并且把这个过滤条件下推到检索层；
切换知识库后要更新前端持有的 `kb_id`，否则会拿着旧 id 去查新库，结果当然是空的。

## 分阶段耗时怎么看

- 模型加载：只发生一次，冷启动项，不要计入单次查询延迟。
- 文档向量化：与语料量线性相关，靠批大小和后端优化。
- 写入 + 刷新索引：数据库侧成本，刷新是同步阻塞点。
- 查询向量化：单条文本，通常几毫秒到几十毫秒。
- 数据库检索：混合检索一次往返，通常十几到几十毫秒。
- 端到端：从按下回车到结果渲染完成，用户真正感知的数字。
