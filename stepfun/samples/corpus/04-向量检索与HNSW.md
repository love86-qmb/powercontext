# 向量检索与 HNSW

## 基本流程

1. 嵌入：把文本编码成定长向量，语义相近的向量距离近。
2. 建索引：暴力检索精确但 O(n) 太慢；近似最近邻（ANN）用图、量化或哈希把复杂度降到次线性。
3. 检索：查询也编码成向量，取 Top-k 后按距离排序。
4. 评价：Recall@k、QPS、P95 延迟。

## 距离度量

- **L2 欧氏距离**：`l2_distance`，未归一化向量常用。
- **内积 IP**：归一化后等价于余弦相似度。
- 归一化很重要：模型输出未归一化时，混用 L2 和余弦会得到不同排序。

## HNSW 的直觉

分层可导航小世界图：上层稀疏、下层稠密，像跳表一样先粗后细地逼近。检索从入口点开始贪心走向离查询更近的邻居。

关键参数：
- `M`：每层邻居数，越大越准也越占内存
- `efConstruction`：建图时的候选队列大小
- `efSearch`：检索时的候选队列大小，越大召回越高越慢

建索引慢的原因：每个新点都要在多层做近邻搜索并连边、再做邻居裁剪，本质是 O(n·M·log n) 次距离计算，且随机访问多、缓存不友好。

## CAGRA 与 GPU 建图

CAGRA 是 cuVS / hipVS 里的 GPU 图索引：把密集距离计算搬到 GPU，建图和查询都走 GPU。seekdb 里 `lib=vsag` 是 CPU 路径，`lib=cuvs` 是 GPU 路径。

计时口径的坑：**第一条查询里的惰性建图必须算进构建时间**，否则性能数字是假的。
