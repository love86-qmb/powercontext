# 混合检索与 RRF 融合排序

## 为什么要混合检索

- 纯向量对**专有名词、型号、罕见缩写**不敏感：嵌入模型没见过，编码出来的位置很随意。
- 纯全文（BM25 / 倒排）对**同义改写**不敏感：问「怎么避免幻读」，文档里写「用间隙锁」，词面完全对不上。

两路各有盲区，所以生产上常用混合检索：向量路召回 Top-N、全文路召回 Top-N，再融合排序。

## RRF 怎么算

Reciprocal Rank Fusion，倒数排名融合：

```
score(d) = Σ_i  1 / (k + rank_i(d))
```

`rank_i(d)` 是文档 d 在第 i 路结果里的名次（从 1 开始），`k` 是平滑常数，常用 60。

**关键性质**：只看名次、不看分数，所以两路的分数不需要可比、不需要归一化。这是它比「加权分数融合」更稳的原因：向量距离和 BM25 分数的量纲完全不一样。

## RRF 的窗口和截断

- `rank_window_size`（窗口）：每路只取前 N 条参与融合。窗口太小，真正相关但排名靠后的结果进不来；窗口太大，噪声变多。
- `rank_constant`（k）：控制名次衰减速度。k 越大，第 1 名和第 10 名的差距越小，融合结果越「平均」。
- 融合后还要再按最终名次截断到 `n_results`。

在 seekdb 里可以这样调（`DBMS_HYBRID_SEARCH` / hybridSearch 的参数）：

```
rank = { rrf: { rankWindowSize: 60, rankConstant: 60 } }
```

## 常见工程坑

- 写完数据要 **refresh index**：异步建索引的库刚写入时查不到，容易误判成 bug。
- 元数据过滤要**下推到检索层**（向量路和全文路各写一次 `where`），不要取回来再在内存里过滤，否则 top-k 会被别人占满。
- 分块策略比模型更影响效果：块太大稀释相关性，块太小丢上下文；把小节标题拼进被向量化的文本通常能明显提升命中。
- **余弦距离和 L2 距离怎么选**：向量归一化后两者排序等价（余弦相似度 = 1 - L2²/2）；未归一化时用 L2，语义检索常用余弦。
